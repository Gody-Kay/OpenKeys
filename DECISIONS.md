# DECISIONS (one line each; newest last; "assumed" = change it if you disagree)

- D001 Language/framework: C++17 + JUCE (real-time audio, one codebase for Linux/Windows/Mac). Python only for tools.
- D002 Licence: open source (assumed). JUCE is free for open-source use under AGPLv3, so OpenKeys will be AGPLv3/GPL. Anyone can use it free.
- D003 Sample engine: sfizz (SFZ). FluidSynth optional for SF2 soundfonts.
- D004 Platform order: Linux first (Kali/Ubuntu with PipeWire/JACK), then Windows (ASIO/WASAPI), then Mac (CoreAudio).
- D005 Working title: OpenKeys (assumed; rename later).
- D006 Own names in UI: Master Knob, Scenes, Setlist, Parts. No Yamaha/Roland names, artwork or copied layouts.
- D007 Sounds: free-to-redistribute licences only (CC0, CC-BY, public domain). Log each library in `content/LICENSES.md`. Never bundle Yamaha/Montage samples or recordings made from them.
- D008 Real instruments recorded by the church's engineer are 100% ours and the best content; target them for Rhodes-style EP, piano, organ, strings, choir.
- D009 Target hardware: 4 GB RAM, Core i5, no GPU. 64-voice default cap, Eco mode, shared reverbs, streamed samples.
- D010 V1 scope = Phases 0 to 5. Church extras, studio, arranger follow as updates.
- D011 Unsigned installers at first (no budget); users click through the "unknown developer" warning.
- D012 Mixer drum-processing is a SEPARATE project and repo. Do not mix code.
- D013 Phase 0 builds with no JUCE (option OPENKEYS_WITH_JUCE, default OFF; JUCE pinned 8.0.4 via FetchContent) so CI is green before lane A adds code. Lane CMakeLists are picked up automatically if present.
- D014 `docs/performance.schema.json` is DRAFT v0 (schemaVersion 0), written by C; needs lane A sign-off before B relies on it.
- D015 Integration tests use stdlib only (no jsonschema) so they run on any CI image.
- D016 Lane A Phase 0 engine is a JUCE-free C++ core (SineEngine behind IEngine); JUCE audio/MIDI wrapper comes once JUCE can be fetched. EngineAPI.h is DRAFT v0.
- D017 JUCE wrapper is a console app (src/engine/Phase0Audio.cpp, target openkeys_phase0, only with OPENKEYS_WITH_JUCE=ON); MIDI->engine via lock-free FIFO; JACK+ALSA enabled on Linux (PipeWire works through either).
- DC1 (C) Lane C tests are Python in CTest: tools/check_presets.py uses jsonschema and exits 77 (skipped) if it is missing; CI installs jsonschema.
- DC2 (C) instrument.ref in presets is relative to content/sounds/. First preset: content/presets/grand-piano.json (Salamander Grand Piano V3, CC-BY-3.0).
- DC3 (C) 2026-11-08 CI must pass on Linux, Windows and macOS (continue-on-error removed). The repo setting 'pin actions to SHA' was turned off.
- 2026-11-08 (C, assumed) DC5: at the user's request this chat (lane C) wrote the Phase 0 UI draft in src/app, acting as Session B. Lives on branch ui-draft, NOT merged to main until it builds. Montage-style layout with our own names; whole screen, no scrolling (D020).
- 2026-11-08 (C, assumed) DC6: root CMake enables C as well as CXX (LANGUAGES C CXX), needed by JUCE gui modules. On ui-draft only until the UI builds.
